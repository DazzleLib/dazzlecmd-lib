# Human Test Checklist: the command guard as a Claude Code hook

**Target version:** dazzlecmd-lib 0.10.47-alpha to 0.10.49-alpha
**Ships with commits:** `0b14fd7` (the guard moves into the library), `37897c5` (its rule choices), `6844656` (audit), `8688a3d` (measurement), `4342a58` (the safedel scope)
**Companion automated tests:** 311 in `tests/test_core_safedel_guard.py` (1 skipped without `DZ_GUARD_COPIES`); mutation report `tests/mutation/v0.10.48__sweep__guard.md`. Full suite: 1,145 passed (Windows), 1,136 passed (WSL).

## What this is

`dazzlecmd_lib/core/safedel/_guard.py` reads each shell line an AI agent is about to run (through a Claude Code `PreToolUse` hook) and refuses the shapes that hid the 2026-11-17 loss: a `dz safedel` whose result is not checked -- piped, joined with `;` or `||`, output thrown away, backgrounded, or run without `--yes` -- or chained with more deletions; and `git worktree remove` / `git clean` on their own. By default it judges nothing else: a plain `rm -rf`, `git checkout --` or a forced push pass untouched. `DZ_GUARD_SCOPE=full` turns on the whole table. This checklist is for a person in a real Claude Code session: what a refusal looks like to the agent, whether ordinary work flows, and how to switch the guard off.

## Prerequisites

1. Claude Code, opened in a project folder whose `.claude/settings.local.json` holds the hook entry:
   ```json
   "hooks": { "PreToolUse": [ { "matcher": "Bash|PowerShell",
     "hooks": [ { "type": "command", "command": "python -I \"C:\\Users\\<you>\\claude\\hooks\\safedel-guard\\_guard.py\"" } ] } ] }
   ```
   with `_guard.py` copied from the library to that folder.
2. Every line below is safe even if the guard fails to block it: the paths do not exist. Never test the guard with a path that holds anything.
3. The guard writes refusals to `%USERPROFILE%\claude\logs\dz-guard\guard.jsonl` (or `$CLAUDE_USER_DIR/logs/dz-guard/`). `DZ_GUARD_LOG=off` turns logging off.

## High-Value Verification (~5 minutes)

### HV.1 -- the incident's pattern is refused, with a reason the agent can act on

- [ ] **Steps:** ask the agent to run exactly: `dz safedel --yes no-such-path-123 2>&1 | tail -1`
- [ ] **Expected:** the tool call is blocked before it runs. The agent sees "BLOCKED by the dz deletion guard -- rule R4", the reason (a pipe replaces the exit code and trims the output), and "Do this instead: dz safedel --yes <path>". The last line reads `guard: BLOCKED R4 safedel.stage`.
- [ ] **Why this matters:** this is the shape of the 2026-11-17 line. If it runs, the guard is not installed.

### HV.2 -- the safe form passes

- [ ] **Steps:** ask the agent to run `dz safedel --dry-run no-such-path-123`, then `cd %TEMP% && dz safedel --dry-run no-such-path-123` (Git Bash: `cd "$TEMP" && ...`).
- [ ] **Expected:** both run; safedel itself reports the missing path.
- [ ] **Why this matters:** the guard must not get in the way of the right way to delete.

### HV.3 -- ordinary work is not policed

- [ ] **Steps:** ask the agent to run `rm -rf no-such-dir-1 && rm -rf no-such-dir-2` and `git status && git checkout -- no-such-file.txt` in a scratch git repository.
- [ ] **Expected:** both run (git complains about the missing file). Nothing is blocked: neither line has a `dz safedel` step.
- [ ] **Why this matters:** the maintainer's ruling: police `dz safedel` lines, not the whole system.

### HV.4 -- the incident's own command is refused on its own

- [ ] **Steps:** ask the agent to run `git worktree remove no-such-worktree`.
- [ ] **Expected:** blocked, rule R1, with the safe replacement (`dz safedel --yes <worktree>`, then `git worktree prune`).

### HV.5 -- PowerShell is judged too

- [ ] **Steps:** with the PowerShell tool, ask the agent to run `dz safedel --yes no-such-path-123 | Out-Null`.
- [ ] **Expected:** blocked, rule R4.

## Section 1: switches

### 1.1 Turn the guard off for one session
- [ ] Start Claude Code with `DZ_GUARD=off` in its environment (cmd.exe: `set DZ_GUARD=off`; PowerShell: `$env:DZ_GUARD = "off"`; POSIX: `export DZ_GUARD=off`), then repeat HV.1.
- [ ] **Expected:** the line runs (safedel reports the missing path). The variable is the harness's environment, not the command's, so an agent cannot switch the guard off by writing `DZ_GUARD=off` in front of a command.

### 1.2 The whole table
- [ ] Start Claude Code with `DZ_GUARD_SCOPE=full`, repeat HV.3.
- [ ] **Expected:** `rm -rf no-such-dir-1 && rm -rf no-such-dir-2` is blocked (R2); `git status && git checkout -- ...` is blocked (R3).

### 1.3 Remove the hook
- [ ] Delete the `hooks` block from the project's `settings.local.json` (a backup of the file from before the install sits beside `_guard.py`), restart the session, repeat HV.1.
- [ ] **Expected:** the line runs.

## Section 2: what the agent does next

- [ ] After HV.1, does the agent rewrite the command as one step and read safedel's last line, without being told? Note what it did.
- [ ] Is the refusal text readable in the terminal (no garbled characters on codepage 437/1252)?
